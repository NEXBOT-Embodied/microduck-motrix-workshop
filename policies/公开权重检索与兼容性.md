## 3. 推理输入、输出与normalizer

官方运行库与导出图给出的观测契约如下。gyro、重力和速度命令按trunk frame表达；重力是将世界单位向量 `[0,0,-1]` 逆旋转到机身坐标；MuJoCo四元数约定为 `[w,x,y,z]`。

| 输入切片 | 内容 |
|---|---|
| `[0:3]` | 机身角速度，rad/s |
| `[3:6]` | 机身坐标下单位重力向量 |
| `[6:20]` | 14关节位置减HOME，rad |
| `[20:34]` | 14关节速度，rad/s |
| `[34:48]` | 上一步未缩放的原始策略输出 |
| `[48:51]` | vx、vy（m/s）、yaw rate（rad/s） |
| `[51:55]` | 4个头颈关节相对HOME的命令，rad |
| `[55:61]` | 身体偏移 `[x,y,z,roll,pitch,yaw]`，m / rad |

关节顺序与本课模型一致：

```text
left_hip_yaw,left_hip_roll,left_hip_pitch,left_knee,left_ankle,
neck_pitch,head_pitch,head_yaw,head_roll,
right_hip_yaw,right_hip_roll,right_hip_pitch,right_knee,right_ankle
```

策略14维不含真实runtime额外的mouth舵机。输入位置相对HOME，不能使用未经处理的绝对角度；动作是位置偏移，官方 `target = HOME + raw_action × 1.0`，控制频率50Hz。头部命令放入观测后不能在输出端再加一次。

normalizer已烘入ONNX图，不能另套一层训练normalizer。Python原型仍保留旧51维模式，必须显式 `--new-cmd-obs` 才构造当前61维输入；原型还依赖 `termios` / `tty`，不能假定原样支持Windows。

## 4. 为什么不能注册FastSAC starter

| 项目 | Pollen官方ONNX | 本课固定任务 |
|---|---|---|
| actor观测 | 实测61维，含头部/身体命令 | 55维，字段还包含本课步态相位 |
| 动作 | 14维位置偏移，scale1.0 | 14维位置偏移，scale0.5 |
| 训练框架 | mjlab / PPO / rsl_rl | MotrixLab / FastSAC |
| 执行器背景 | 现代训练使用BAM XL330电压/摩擦/延迟模型 | 本课固定Motrix任务执行器 |
| 文件内容 | 推理网络及normalizer | 续训需要对应actor/critic/target/optimizer、计数与run元数据 |

相同关节数和机器人外形不足以证明兼容。ONNX没有完整FastSAC续训状态，不能用补零、裁维、改扩展名或单独导出actor冒充兼容starter。

可以参考其控制接口和奖励设计，也可以另立研究任务做完整61维推理适配；后者需要匹配HOME、动作尺度、50Hz、normalizer、坐标、执行器和碰撞，并在MotrixSim中单独验收。本次没有实现或宣称该适配已通过。

课程的reference/starter应来自本课兼容训练run并通过实际行走验收。若使用公开Pollen策略做对照展示，应明确标为“Pollen公开策略推理基线”，不能称为本课训练成果。
