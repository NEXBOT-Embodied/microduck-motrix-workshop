# 教师镜像准备包

当前交付是镜像源文件和构建/验收步骤，尚无已打包的 VM、容器镜像或已发布 RoboGo 模板。RoboGo 与算力自由接入格式、GPU 调度和图形访问方式尚待供应方确认。

推荐先在平台提供的一台 Linux GPU 测试实例中验证，整套课程放在 `/opt/microduck-course` 或平台分配的课程工作目录。每人获得可写工作副本和独立 outputs，不让 50 人共写教师目录。

镜像应包含：固定版 MotrixLab 源码与锁文件、完整 MicroDuck 网格、MotrixSim SDK、Torch/FastSAC 依赖、可访问的远程图形环境、课程 package、参考/起步真实策略与元数据、教师 PPT/手册/FAQ、已录制真实演示视频。无需 Sim2Real/硬件控制栈。

## 构建顺序

1. 供应方确认镜像格式（整机模板、Docker 还是平台环境快照）、GPU 型号/驱动、系统、远程桌面、学员目录隔离和持久盘。
2. 教师在测试实例准备所需图形运行库和 NVIDIA 驱动。
3. 在工程根目录运行 `sh image/prepare_linux.sh --apply`。它调用课程安装器，以 CUDA 12.8 配置安装固定版 MotrixLab 和课程包，并导出依赖版本。依赖下载需要网络和可访问的 MotrixSim SDK 源。
4. 核对脚本保存的 `image/runtime-freeze.txt`。
5. 运行 `check --runtime`，再做官方/本课程训练及 MotrixSim 窗口和离屏录制验收。
6. 实际训练并观看 reference、starter，填写 `configs/policies.yaml`。两项当前均缺失，构建脚本不会生成假权重。
7. 冷启动复制 2 份学员实例，逐项验证文件写入、策略保存、端口和桌面相互隔离；之后按验收计划逐级升至 50 人真实并行训练。
8. 冻结版本、保存 `uv.lock` 与 `uv pip freeze`、包清单、平台模板 ID、教师演示视频及验收记录。平台 ID/账号等保存在主办方私密清单，不写入可公开课程仓库。

## 提供给平台方的确认事项

| 项目 | 必须拿到的答复 |
|---|---|
| 并发使用方式 | 50 人每人独立代码、训练进程、仿真实例与可写盘；同镜像可创建多实例 |
| GPU / CPU | 单用户配额、50 人同时训练的总配额、超额行为、排队是否会中断课堂 |
| 图形能力 | MotrixSim 原生窗口通过什么桌面/流媒体协议访问，或是否支持真实离屏渲染 |
| 持久化 | 断线、实例重启后代码/checkpoint/日志是否保留 |
| 模板发布 | 教师复制模板的权限、版本冻结、回滚方式、是否可禁止学生改共享基镜像 |
| 登录 | 主平台和备用平台各至少覆盖最终名单，课前实测有效，不在材料中公开账号 |
| 容量 | 登录、同时拉起实例、训练和图形会话分别压测；“50 人登录”不足以证明“50 人独立训练” |

详细运行门槛与记录表见 `acceptance_plan.md`。
