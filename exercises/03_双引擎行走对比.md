# 练习 03：同一策略在两个物理引擎中会怎样？

时间：16:00–16:45，共 45 分钟。最终学生看到的三维结果必须为 **MotrixSim**。

**制作版状态：**第二引擎、迁移线路和前后台交互方式尚未选定，也没有已验证的 MicroDuck 完整双引擎 runner。本页是完整课堂实验设计与验收要求，不能当作迁移功能已交付。未完成实际适配时明确标注未执行，不能用两次 MotrixSim 回放冒充 Sim2Sim。

## 为什么要做

两个引擎可能对接触、约束、积分、执行器或模型导入有不同处理。即使 Actor 权重相同，鸭子的闭环行为也可能不同。实验要定位差异来自哪里，而不是给两个画面取不同名字。

## 完成版的 45 分钟步骤

| 分钟 | 学员行动 | 证据 |
|---|---|---|
| 0–5 | 确认本人策略身份和 Actor 归一化统计 | checkpoint / 统计哈希 |
| 5–12 | 核对模型、14 维动作和 55 维观测合同 | 合同版本与映射 |

| 22–32 | 以相同命令在 MotrixSim 中执行测试 | MotrixSim 实际回放证据 |
| 32–40 | 比较速度、存活、重置与动作变化 | 对照表，说明条件差异 |
| 40–45 | 返回 MotrixSim 展示本人结果 | 本人策略标识与一句解释 |

## 必须对齐

- 一套确定模型变体；网格、惯量和脚底碰撞模型可追溯。
- Actor 观测顺序、坐标、单位、前一动作、相位、归一化一致。
- 14 维关节顺序、默认姿态、动作缩放、控制器、增益和边界一致。
- 0.005 s 物理步长 / 0.02 s 控制周期，或明确记录无法一致的设置。
- 相同速度命令、起始状态、测试时长；区分跌倒、终止与自动重置。

## 不能当作成功的情况

MotrixLab 和 MotrixSim 两个窗口；URDF 与 MJCF 两种文件查看；导出一个 ONNX 文件；另一引擎里只播放预录视频；把 Pollen 另一训练框架中的策略改名。这些都缺少本实验要求的同一真实策略跨引擎证据。
